# 0.6.2の実ページ検証

2026-10-06、Macの既存収集用Chromeで次の店舗を実際に読み取りました。

対象: https://maps.app.goo.gl/p454Vh7YYyWrwpjp8 （いっかくじゅう）

## 修正した問題

- 0.5.0以降の通常実行で、以前の版が使用していた収集サービスのChromeを選ばなくなっていた。全件・期間指定では、起動済みのサービスを再利用するようにした。サービスがない新規導入ではCLI自身のChromeを使用する。
- 期間指定は互換収集経路を選択できなかった。全件を読み取ってから期間を判定する同じ経路にした。
- 既存Chromeへの接続時に `Browser.setDownloadBehavior: Browser context management is not supported` が発生していた。既存ブラウザーの設定を変更しない接続オプションを使用する。[Playwright公式資料](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp-option-no-defaults)
- 短縮共有URLを収集用タブに直接渡すと、そのタブのナビゲーションが終了する場合があった。Googleマップの通常URLへ解決してから渡す。転送先URLを検証し、取得イベントの店舗IDを照合する。
- CLI自身のChromeでは、全口コミへの切り替えを繰り返し押して一覧を先頭へ戻していた。また、表示制限の文言だけで追加読み込み前に操作待ちに入っていた。切り替えは一度にし、通常の追加読み込みが進まなくなった場合に操作を求める。

## 実行結果

検証中に追加のログイン操作は行っていない。これは既存の収集用Chromeを再利用したこのMacでの結果であり、新規プロファイルや別のGoogle側表示条件での取得成功を保証するものではない。

| 検証 | 結果 |
| --- | --- |
| `--all` | 画面332件、重複しない口コミID332件、保存332件、終了コード0で自動終了 |
| 本文あり / 評価のみ | 246件 / 86件 |
| 未取得 / 本文の省略残り | 0件 / 0件 |
| 全件CSV | データ332行 |
| 全件Excel「口コミ」 | ヘッダーを含む333行 |
| `--from 2023-01-01 --to 2026-09-30` | 一覧332件を読取照合、期間内178件、期間外84件、日付要確認70件 |
| 期間Excel | 「口コミ」178件、「期間境界・日付不明」70件、「取得情報」 |
| 期間指定の終了コード | 2。日付要確認が残るため。収集の未取得件数は0件 |

期間内・期間外・要確認の合計が332件になることを確認し、保存CSVとExcelも読み直した。相対日付や編集日は正確な投稿日と扱わず、境界・不明は確認用シートに残す。

## 回帰検証

- Python単体テスト96件が成功。単体テストは実ブラウザーや実サービスへ接続しない。
- TypeScript単体テスト26件が成功。
- 既存Chromeがコンテキスト設定変更を拒否する接続エラーを再現し、既存タブを閉じずに収集できることをテスト。
- 共有URLの解決、転送先検証、別店舗の取得データを追加しないことをテスト。
- 制限の文言が残っていても読み込み中に操作を求めず、全口コミへの切り替えを繰り返さないことをテスト。
- 期間指定でも既存環境を利用し、一覧全件の照合と期間判定を分けることをテスト。
- 型チェックとPython配布パッケージのビルドが成功。配布wheel、導入済みCLI、検証対象ソースの一致を確認。

口コミ本文・投稿者情報を含む検証出力は利用者のMacに保存し、リポジトリには含めていない。
