# 0.6.3の期間指定の検証

2026-10-06、このMacの既存の専用Chromeで確認した。全件の読取と、正確な投稿日による期間抽出は別の結果として記録する。

## 調査結果

利用者の05:42の保存データを、同じ店舗・同じ日の全件データと口コミIDで照合した。期間内と推定した178件と要確認70件のIDは再判定結果と一致した。合計は178件＋70件＋84件＝332件。

一方、表示日付319件は「3年前」などの相対表記で、13件は編集済みの表記だった。正確な投稿日を読み取れた行は0件。推定した日付範囲での判定は再現できても、期間内の全件を正確に抽出できたとは確認できない。

要確認70件の内訳は次のとおり。

| 表記・理由 | 件数 |
| --- | ---: |
| 3年前・開始日の境界にかかる推定範囲 | 47 |
| 4年前・開始日の境界にかかる推定範囲 | 7 |
| 4日前、5日前、1週間前・終了日の境界にかかる推定範囲 | 3 |
| 編集済み・元の投稿日不明 | 13 |

## 修正

- 期間指定で「保存件数が画面総件数と一致」と表示していた箇所を「読取件数」に修正。期間のCSV件数、期間外、要確認を別に表示する。
- 期間外の行もExcelの「期間外」とJSONの `excluded_reviews` に保存。期間内・要確認・期間外の区分を合わせると読取全行になる。
- 正確な日付表示の件数、相対表示から推定した件数、投稿日不明件数を取得情報に保存。
- 推定範囲の境界にかかる行が0件でも、相対表記があれば正確な期間抽出の成功として扱わない。`period_date_accuracy_verified` をfalse、終了コードを2とする。
- 日付範囲の丸め仮定や編集日を元の投稿日として扱わない方針は維持。正確な日付を追加取得できたという変更ではない。

## 実際のCLIでの再確認

0.6.3のCLIを、保存済みデータによる再計算とは別に実行した。

```bash
google-maps-reviews "https://maps.app.goo.gl/p454Vh7YYyWrwpjp8" --from 2023-01-01 --to 2026-09-30
```

検証では保存先だけ一時フォルダーへ変更した。収集日時は2026-10-06 11:12（UTC+07:00）。

| 確認項目 | 結果 |
| --- | --- |
| 画面総件数・一覧読取件数・重複なし口コミID | 332件で一致 |
| CSV・Excel「口コミ」 | 期間内と推定178件 |
| Excel「期間境界・日付不明」 | 70件 |
| Excel「期間外」 | 期間外と推定84件 |
| JSONの3区分の合計 | 332件。重複・欠落なし |

| 読取件数の照合 | `scan_coverage_verified: true` |

| 終了コード | 2。期間抽出の精度が未確認のため |

CSV・Excel・JSONを読み直し、各件数と口コミIDの集合を確認した。この実行の全332件のIDは同日の以前の全件収集と一致した。

## 回帰・配布の確認

- Pythonの98テストが成功。期間外行の保存と数式文字列の処理、4件の全読取データが重複・欠落なく3区分に残ること、境界行がなくても相対日付を正確な抽出成功にしないことを含む。
- wheel・sdistをビルドし、wheel内のCLI・日付処理・バージョンがソースと一致することを確認。
- このMacの既存pipx版を0.6.3へ更新。インストール済みCLIのソースとリポジトリの一致、バージョン表示を確認。

この検証は上記店舗と既存ブラウザー環境での結果。別店舗・別日時・新規プロファイルでも同じ結果になる保証や、正確な投稿日による期間抽出の完了を示すものではない。
