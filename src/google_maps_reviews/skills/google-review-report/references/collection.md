# 指定施設の口コミ収集と復旧

URLだけを受け取った場合の対象は、そのURLの施設だけ。既存JSONや準備済みフォルダーを自動探索して代用しない。利用者が既存ファイルを明示した場合はその入力を使い、URLも指定されていれば展開後の施設IDと施設名を照合する。

## 接続・起動に失敗した場合

1. 直前のCLIの標準エラーと終了コードを確認する。0.5.0以降の `report prepare` は、旧Web用収集サービスを呼び出さずPythonの専用ブラウザーを直接使う。Node.js・Vercel・収集サービスを起動する必要はない。古いCLIならREADMEのインストーラーで更新する。
2. 専用ブラウザーが別の収集で使用中なら、並行して起動せず完了を待つ。通常のChromeや他の作業のブラウザーを終了しない。プロファイル、ログイン状態、既存の分析を削除しない。
3. 一時的な接続エラーなら、同じURLで新しい出力先に1回だけ再試行する。省略時の出力先は毎回新規になる。失敗したフォルダーにmanifestがなければ `report resume` は使えない。
4. ログイン・確認画面が必要なら、指定施設の専用Chromeで利用者に操作を案内する。`--manual` はEnter入力ができる対話ターミナルでだけ使う。入力できない実行環境で起動して待ち続けない。
5. 再試行しても取得できない場合は、今回のURL、実際の取得件数、直前のエラー、次に必要な操作を短く伝えて止める。収集失敗を全件取得・分析完了として報告しない。

ブラウザー操作ツールを使う場合も指定施設の確認と復旧に用途を限定する。別店舗のタブ・履歴・デスクトップの口コミファイルを分析入力にしない。

## 取得後の照合

今回の保存先のmanifestとsourceのmetadataを読み、以下を確認する。

- requested_url：今回入力したURLと一致。
- resolved_url：CLIが指定URLを開いた直後の展開先。
- source_url・place_name：取得画面の施設URLと名称。施設IDが取得中に変わっていない。
- coverage：保存件数、画面件数、重複なしの照合、省略の有無、停止理由。

旧バージョンの既存JSONはrequested_urlを持たないことがある。利用者がそのファイルを明示した場合に限り、source_urlと施設名から確認する。短縮URLだけ、ファイル名だけ、施設名が似ているだけでは一致を確定しない。部分取得なら取得した範囲のレポートとして扱い、未取得分を作らない。
